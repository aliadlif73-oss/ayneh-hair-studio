# Ayneh project workflow

- This project is the independently rebuilt Ayneh hair consultation application.
- Keep the GitHub repository synchronized with every user-requested code change. Commit and push the validated source to GitHub before reporting completion. If blocked, clearly report that GitHub is not synchronized.
- Preserve the Sites project identity in .openai/hosting.json and its configured audience. The current user brief requests public salon pages; keep all customer data and manager operations protected server-side. Sites remains the deployment target; GitHub stores source and runs validation, not the production Worker.
- Never commit API keys, credentials, customer photos, generated customer output or local environment files.
- Run bash scripts/build.sh and node scripts/validate-artifact.mjs before publishing.
- Do not claim live KIE generation has been tested without a successful real request.
- Salons run day to day from the Telegram/Bale bot. A salon that bought a plan also gets the key-login panel at /panel (owner's decision): its page, plan, image credits and top-ups. Unpaid salons have no panel. The bot (worker/telegram.js, one code path for both; Bale gets plain text). The owner console is /admin. Booking exists only as the owner asked for it: a salon on PRO or SIGNATURE (or the 3- or 6-month «پنل آرایشگاه») sets a day and time for a request in /panel (worker/panelapi.js, table bookings); following customers get the confirmation, a day-before reminder and one after-visit follow-up on Telegram/Bale only. Do not add customer self-booking, SMS reminders or other booking features without being asked. SMS exists only for two things the owner asked for: the one-time code that verifies a customer's mobile before generation (worker/sms.js) and the salon-link text a salon triggers from the Telegram bot. Keep MELIPAYAMAK_TOKEN secret; do not add other SMS uses without being asked.
- Catalog photos in public/catalog are generated by .github/workflows/catalog.yml; never commit placeholder images there.
- Usage stats (worker/stats.js) use only an anonymous random browser id and event names; never log names, mobiles, photos or IPs into events_log.
- Staff referrals (worker/referral.js): the first link wins and is permanent; only the salon manager moves a customer. A member's customers' requests go only to that member, never to the manager or other members. The server alone decides the owner of a request. Customer photos and submissions are kept permanently by the owner's decision; do not reintroduce automatic deletion without being asked.
- Owner alerts (worker/alerts.js): every bot action that can fail must reply to the sender in plain Persian and call notifyOwner; activity and alerts never contain customer mobiles or photos.
- Service lines (worker/lines.js): hair = hairstyle only (keeps her colour), color = hair colour only (keeps her haircut; may use her own hairstyle result as base_id), nails, lashes. The owner removed the consent checkboxes: keep the short notes under «بساز» and the send button instead of adding checkboxes back.
- Image quota (worker/server.js QUOTA_PER_LINE): each person (session, browser id, verified mobile) gets 3 images per service on a salon page (12 in all; the 360 view counts as hairstyle; failed images do not count). Trial and demo pages keep their own budgets. Do not raise it without the owner asking.
- Team mobiles without image limits live only in the database (app_settings key unlimited_phones, a JSON list of +98 numbers); never put phone numbers in the code or the public repo.
- Public pages (owner's decision): "/" introduces Ayneh only (benefits, sample work per service, FAQ, one CTA box per service, each addressed to that specialist). Each service has its own page built from one template: /hair (hairstyle), /color (hair colour), /nails, /lashes; plus /salon-panel (the salon panel) and /sample (the 3-step sample builder; /try is the regular customer page). The home page demo («خودتان امتحان کنید.») has four service chips. All pages are built from one source by design/landing/build.py; never hand-edit worker/landing.js. REAL_SAMPLES in build.py holds the owner's illustrative pairs, labelled «نمونهٔ نمایشی · تقریبی»; never label them «ساخته‌شده با آینه» until they are real Ayneh results.
- Plan names shown to people are Persian (owner's decision): ESSENTIAL «پایه», PRO «حرفه‌ای», SIGNATURE «کامل». Plans follow the owner's price sheet exactly (design/landing/build.py PLANS → worker/prices.js): ESSENTIAL 1 month 2.9M toman (20 gift images), PRO 3 months 6M (was 8.7M, 75 images), SIGNATURE 6 months 10M (was 17.4M, 180 images, «پیشنهاد آینه»); after the gift credit, every 10 images cost 200,000 toman. These are single-service plans. «پنل آرایشگاه» (SALON_PLANS → prices.js salon1/salon3/salon6): every service for up to 3 users (the manager is one): 1 month 5M, 3 months 10M, 6 months 15M; each user beyond 3 costs 2M / 1.5M / 1M toman for the whole period; total = base + max(0, users−3) × rate, computed on the server (orders.users). Its gift images are the same-length single plan × 2 (40/150/360) and it opens the features of the same-length tier — both assumptions in build.py until the owner says otherwise. Plan copy is the owner's wording; change it only when the owner asks.
- Image credits (worker/credits.js): only salons with a paid plan are metered. A confirmed plan grants its images and runs for its months; renewing extends the same salon. Spending is the salon's non-failed generations since its plan started. At zero credits, or after the plan ends, generation stops with a plain Persian message and an owner alert (no customer mobile or photo). The per-person QUOTA_PER_LINE still applies on top.
- Checkout (worker/orders.js): amounts come only from prices.js; confirmation is atomic (one salon, one grant); the panel cookie is a random session token (panel_sessions), never the key or its hash. Payment is confirmed automatically by the payment site's webhook (/api/pay/confirm) only: there is no customer receipt or manager-approval step (owner's decision); the /admin confirm is an emergency path never shown to customers. A webhook after the 10-minute window confirms only when it reports the exact amount; a wrong amount, an unknown code or a cancelled order opens nothing and alerts the owner. Legacy 'reviewing' orders never expire.
- End of credit (owner's wording): the panel stays open with its data and customers, generation stops, and /panel says «اعتبار پنل تمام شد. نمونه‌سازی متوقف شده. برای ادامه تمدید کنید.» with «تمدید پنل»; 7 days before, «اعتبار پنل نزدیک به پایان است.». After purchase the panel home shows «پنل شما باز شد.» with the four-step checklist (panelDashboard checklist, ticks in salons.settings.checklist). The customer result offers «قالب استوری اینستاگرام» (worker/customer.js storyBlob): the result itself untouched and unfiltered on a 1080×1920 frame, signed with the salon's logo and name on salon/member pages and Ayneh's logo on Ayneh's own pages (direct, demo).
- Panel self-service (worker/panelapi.js): every paid salon edits its page details and adds/removes portfolio photos in /panel («صفحهٔ من»), and renews or upgrades from «پلن و ارتقا» (worker/orders.js createRenewal: same salon, same panel key, same checkout). The panel shows tabs only for what the plan opens; setup steps ask only for what the plan has (every paid plan has the bot). A salon on «پنل آرایشگاه» renews only within it (going back to one service is a support call).
- A paid salon's public page never carries the buyer's own name or mobile: provisioning copies neither; the salon writes the page phone itself in «صفحهٔ من». Salons made before that fix were cleaned by drizzle/0017_buyer_contact_cleanup.sql (only values still equal to the copied ones). Ayneh's one public support number (09933773515, with Telegram and WhatsApp links; no Bale contact) lives in worker/support.js (build.py checks the landing matches).
- Services sold: hair (hairstyle), color (hair colour), nails, lashes; «پنل آرایشگاه» is all four. A salon on a single-service plan offers only that line on its customer page and in requests (settings.lines, written by worker/credits.js applyPlan; read by worker/plans.js linesOf). A salon that bought «مدل و رنگ مو» before the split (settings.service 'hair', no lines) keeps hairstyle + colour (drizzle/0018 writes it out; the code keeps the fallback). Salons without a plan keep all four.
- User cap (worker/referral.js createStaff): «پنل آرایشگاه» allows the manager + (seats − 1) active members, seats = settings.plan.seats (3 + paid extra users); the console and the bot refuse the next member in plain Persian. The manager's own member row is never capped. Single-service plans have no user cap.
- Public copy states only what Ayneh does: no customer self-booking or daily-report claims, no placeholder testimonials or sample counters. What a salon buys is a «پلن»; «پنل» is where it logs in.
- Plan features (worker/plans.js): ESSENTIAL = page, gallery, reference photo, requests in /panel and the Telegram/Bale bot (every paid plan has the bot); PRO adds booking & follow-up and the simple report; SIGNATURE adds the full report, the customer archive (search + CSV) and priority support. Salons without a plan keep everything. A paid salon whose bot is not linked yet receives its manager-scope requests in /panel (leads.status='panel'); a member's customers still go only to that member. The weekly bot summary and every report carry counts only — no customer names, mobiles or photos.
- Visitor demo (worker/demo.js, owner's decision): /s/demo asks for no mobile and makes 2 images per visitor (session + anonymous browser id; failed images do not count), behind a coarse per-network counter (hashed IP in `limits`, DEMO_IP_DAILY per 24 h) and the salon daily cap. Clearing cookies and storage gives 2 more until those stop it; that is the accepted trade-off. Salon customers keep QUOTA_PER_LINE.
- Generation time (worker/timing.js): every successful image stores its measured duration (generation_timings); the owner sees median / p90 / slowest in /admin. Never state a duration in public copy («کمتر از یک دقیقه») until real requests have been measured there.
- Regular customers (worker/customers.js, regular.js, regularpage.js; prices in worker/customerprices.js, never in the generated prices.js): /try embeds the direct salon (fixed id ayneh-direct, owner_id 'direct') with 3 free images in all, then packs 6/9/12 or any count at 30,000 toman per image, computed on the server. A pack is an order of kind 'customer_pack' confirmed by the same confirmOrder / webhook; its images go to her own account (customer_ledger, bound to her verified mobile, or to the browser id only when SMS is off) and are never taken from a salon credit (generations.paid_by). On a salon page the pack sheet appears only after her QUOTA_PER_LINE images for a service are used, without the referral card; sending to the salon stays.
- Referral rewards (worker/rewards.js): ?ref=CODE on a public page sets a first-party cookie; a plan order opened with it is rewarded only when confirmed: the buyer salon and the referrer (salon credit_ledger, or the customer's own account) get REFERRAL_IMAGES each, once per order and once per buyer salon, never to oneself, with no cap (owner's decision). The salon's link is in /panel.
- Site icons (owner's decision): public/favicon.ico, favicon-32.png, apple-touch-icon.png, icon-192/512.png and site.webmanifest are made from the Ayneh logo on the cream background; every page head links them.
