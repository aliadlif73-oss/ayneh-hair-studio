# Ayneh project workflow

- This project is the independently rebuilt Ayneh hair consultation application.
- Keep the GitHub repository synchronized with every user-requested code change. Commit and push the validated source to GitHub before reporting completion. If blocked, clearly report that GitHub is not synchronized.
- Preserve the Sites project identity in .openai/hosting.json and its configured audience. The current user brief requests public salon pages; keep all customer data and manager operations protected server-side. Sites remains the deployment target; GitHub stores source and runs validation, not the production Worker.
- Never commit API keys, credentials, customer photos, generated customer output or local environment files.
- Run bash scripts/build.sh and node scripts/validate-artifact.mjs before publishing.
- Do not claim live KIE generation has been tested without a successful real request.
- Salons have no panel: they use the Telegram/Bale bot (worker/telegram.js, one code path for both; Bale gets plain text). The owner console is /admin. Booking exists only in the four specialist editions, at the owner's request (worker/booking.js, loaded only by worker/edition-entry.js and gated on SERVICE_LINE); never add booking to the main multi-salon app without being asked. SMS exists only for what the owner asked for: the one-time code that verifies a customer's mobile before generation (worker/sms.js), the salon-link text a salon triggers from the Telegram bot, and, in the specialist editions only, the booking-confirmed text (MELIPAYAMAK_BOOKING_BODY_ID, no link). Keep MELIPAYAMAK_TOKEN secret; do not add other SMS uses without being asked.
- Catalog photos in public/catalog are generated by .github/workflows/catalog.yml; never commit placeholder images there.
- Usage stats (worker/stats.js) use only an anonymous random browser id and event names; never log names, mobiles, photos or IPs into events_log.
- Staff referrals (worker/referral.js): the first link wins and is permanent; only the salon manager moves a customer. A member's customers' requests go only to that member, never to the manager or other members. The server alone decides the owner of a request. Customer photos and submissions are kept permanently by the owner's decision; do not reintroduce automatic deletion without being asked.
- Owner alerts (worker/alerts.js): every bot action that can fail must reply to the sender in plain Persian and call notifyOwner; activity and alerts never contain customer mobiles or photos.
- Service lines (worker/lines.js): hair = hairstyle only (keeps her colour), color = hair colour only (keeps her haircut; may use her own hairstyle result as base_id), nails, lashes. The owner removed the consent checkboxes: keep the short notes under «بساز» and the send button instead of adding checkboxes back.
- Image quota (worker/server.js QUOTA_PER_LINE): each person (session, browser id, verified mobile) gets 3 images per service on a salon page (12 in all; the 360 view counts as hairstyle; failed images do not count). Trial and demo pages keep their own budgets. Do not raise it without the owner asking.
- Team mobiles without image limits live only in the database (app_settings key unlimited_phones, a JSON list of +98 numbers); never put phone numbers in the code or the public repo.
